# Optional twin-arm bridge: design proposal only

**Not implemented, not released.** This is not part of the v15 disconnected-floor/camp-access repair. Coordinates, resource budgets, rewards and generation probabilities remain undecided.

## Player decision

A visible keyed winch connects to two raised bridge arms. Spend one existing key to lower exactly one arm; the other locks permanently. One arm buys a shorter or less costly optional approach; the other reaches a guarded optional reward. Preview the target, remaining battles, reward and irreversible loss of the alternative before confirmation. No new inventory resource or separate menu is needed.

## Geometry and rule boundary

- Build a dedicated optional zone in a future map family, not a patch over current proven chokepoints.
- Keep both ordinary main routes available before and after either bridge choice. Refusing or lacking a key must not prevent normal progression or returning to the camp.
- Any paid shortcut that bypasses a guard must be represented as an explicit keyed bypass in that future family's validator. Do not quietly weaken the current “route guards are mandatory” proof or claim it still holds unchanged.
- The keyed bypass must **not bypass a reward door**. A guarded reward must remain accessible only through its declared paid entrance and intended guards, with no neighboring-floor leak or bridge-backside entry. If the bridge payment is intended to replace a door payment, that requires a separate explicit future contract, not an assumed exception.
- Arrival, exit, stairs, safe walking, camp access and irreversible-choice recovery all require independent connectivity checks. No branch may strand the player.
- Key supply and reward value need a concrete, independently tested budget. No assumed free key, mandatory random drop or untested profitability guarantee.

## Flat visual language

Use folded planks and an unmistakable gap for raised bridges, continuous planks for a lowered bridge, and a physical cross-pin for the rejected arm. Trace both arms to a single winch with visible chains. No letters, 3D illusion, licensed assets or color-only state changes. Keep pathways and actors readable at 64px.

## Acceptance required before any release

Prove both normal routes remain, the chosen optional path alone opens, the other stays closed, reward gates cannot be bypassed, payment occurs once, cancellation is free before confirmation, replay preserves the decision, and old rule versions are untouched. Native play must demonstrate both choices and a no-key refusal. This document is not evidence that any of those behaviors exist yet.
