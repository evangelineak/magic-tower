# 跨局档案与风险模式：分批实施计划

状态：开发与验证中；目前游戏/网页没有跨局结算或真实死亡。本文件不构成功能完成声明。公开网页维持v0.17。

## 第一批：可验证存储与纯结算模型

先隔离实现，不改现有journey-v4.json。档案记录版本、revision、首次楼层里程碑、解锁标识和每run_id唯一结算收据。首次实际到达3/5/8层分别解锁一个横向备选标识（legacy_scout/tactician/veteran），目前不加永久属性，不冒称已经实现天赋效果。全生涯最多三个首次目标；不是每次失败都发点。

结算从经过World验证的已保存快照取得最高到达层、种子、步数和结束结果。UI不能直接声称到达8层或已胜利。首章击败K后仍可继续远征，不自动终止该run；只有明确选择结束或最终胜利后确认结算。

纯档案函数保证无输入副作用、相同run_id同摘要幂等、不同摘要冲突仍保留原收据、同里程碑不重复发放、损坏不静默清空。它不提供真实并发锁或落盘保证。存储层须另行验证。

## 浏览器事务，不依赖WebGL

独立IndexedDB原型，在同一readwrite事务里完成档案、收据和run结束标记；仅oncomplete后报告成功。两个真实同源标签测试writer fence、expected revision、租约接管、旧writer拒绝、故障abort、关闭重开持久读。BroadcastChannel不是锁。仅按run锁不够：新局切换和单槽active pointer也需全局fence，旧标签不能用另一个run_id覆盖新局。

原型使用单独数据库，不触碰当前游戏IndexedDB或用户存档；无WebGL需求，不能因此冒称最终Godot Web接入已验证。

## 原生端与迁移

考虑单容器档案＋active run，避免两个文件先后写导致半提交；短生命周期原子目录锁、已校验备份和临时写入后原子替换。必须明确进程崩溃/锁遗留/无权限/磁盘写失败的行为。不能承诺硬件掉电时绝对持久，也不能未经验证将原子rename当成浏览器事务。

旧档缺少原生run_id，无法从不同历史快照恢复同一旅程身份，因此继续原玩法但不参加跨局奖励；新局才登记可结算ID。不能随机补ID或按快照hash重复领取；同种子的新局必须仍是不同ID。整套本地数据回滚或手工修改不是离线反作弊保证；不要为单机游戏引入侵入式保护。

## 后续：真实风险模式和天赋抽选

默认仍保护致死战斗。风险模式必须开局明确选择，致死行动再次确认；不能把撤离叫死亡轮回。确定死亡后不允许Undo复活，敌人不删除、不发击杀或金币、不计算战后治疗。当前伤害模型是整场确定性结算，若未实现逐击死亡时间线，不得用完整击杀轮数冒充死亡时真实回合。

结算提交失败须显示未成功且允许重试，不发奖励、不悄悄开新局。已提交收据后旧快照只能查看/非计奖复盘，不能再次结算。解锁天赋与局内候选池的具体代价、抽选和显示在下一小批实作，保留原始无传承选项和可预测伤害。

## 已取得的隔离验证（仍未接入游戏）

- 纯GDScript档案189项通过；37组实际生成协议向量及计数器边界在Node执行269项，结果和输入不变性一致。
- 真实Chrome、同源两个标签使用独立测试数据库：最终源24项IndexedDB自测及人工争写/过期接管/旧标签拒绝/abort/幂等/关闭重开通过。WebGL限制不影响此项测试。
- 原生单容器存储已实现并独立通过88项检查，包括坏档拒绝、备份、临时写、rename前失败保持原状态、rename后结果不明重新查收据；真实两个Godot进程同步竞争已验证单赢家：一次败方被短锁拒绝，另一次败方在锁释放后被旧revision拒绝，最终只有一次提交。
- 以上使用6字段模拟快照，不是完整World存档。尚未实现JavaScriptBridge游戏适配、后台心跳、断线只读提示、跨局界面、天赋效果或风险死亡流程。受控事务abort不能冒充进程kill/硬件断电验收。
