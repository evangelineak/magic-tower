# 受约束的整层生成

v0.11 将非零种子从两个小区域的墙体模板，改为每层选择一个完整的作者骨架，再按预算安置普通物品和怪物。仍是五层原型，不是无限章节或任意房间拼接器。

## 三种路线语义

- **环廊 `ring`**：在不消耗钥匙、不穿水、不击败宝库守卫的几何图上，入口到本层目标没有单个必经中间格，玩家可以绕行。
- **双庭 `courtyards`**：不同资源支庭通过枢纽连接；关闭普通锁门时，主线必须经过 `(4,5)`。
- **脊道 `spine`**：主走廊配支路，选择深入支路意味着折返；关闭普通锁门时，主线必须经过 `(2,8)`，而 `(4,5)` 保持为墙。

这三种路线不是镜像，也不叠加旧的小区域开墙模板，以免把骨架的关键结构打穿。坐标用于工程验证，不要求玩家记坐标。

## 保留什么，随机什么

楼梯、商人、制图员、阀门、机关芯、电梯、工坊、调查样本、碑文、奇遇、钟台、固定守卫及奖励门的位置不变。额外保留奖励笼上方墙、宝库上下围墙和水区西侧封墙，防止几何随机把机会成本消掉。

普通敌物的每层种类和数量预算不变，但会在新骨架的可用格子中重新安置。干区、湿区按种类分别分池：原来需要排水/造桥才能取得的攻击宝石仍留在湿区，不会变成免费的干路成长；主路钥匙也不会被随机藏进水后。

种子0保留作者基线。非零种子的新开局会因生成器升级而改变；存档保存完整地图，读档不会按新版骨架重新抽取。

## 三层验证，不宣称任意走法都安全

1. 骨架语义：目标可达，环廊／枢纽／脊道的结构约束在覆盖特殊物后仍成立。
2. 门控拓扑：关键特殊物可达，宝库守卫、奖励笼门、水域各自不能被绕过；打开对应阻挡后奖励可以到达。
3. 真实战斗见证：使用同一 `Progression.battle` 计算一条不借贷、不花钥匙、不排水、不用技能、天赋、特殊装备或奖励笼的通关路线，再在测试中用真正 `World.step` 重放。

验证器是保守的找路启发式，不是全局最优解求解器。“未找到保守路径”不等于证明该候选绝对无解。候选失败最多重试16次，再回退经过验证的作者基线；基线也不合法则阻止开始。

可证明存在通关路线，不代表玩家错误选择后仍一定能赢，也不保证可收齐所有可选奖励。
