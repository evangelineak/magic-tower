# 全球榜前置：本地 v5 重放基准

测量时间：2026-11-09 03:35 UTC。基线源码：`4eed4b6f07d37e3cfffa548319deabfe3ab5bb80`。Godot `4.6.3.stable.official`，Linux x86_64（6.18.57），环境报告 CPU 为 AMD EPYC 9V74；这是共享执行环境，不是独占硬件或生产服务。

**结论：实际规则重放成本不能用“只是提交一个分数”忽略。这里没有实现服务器验算服务，没有 Worker 性能数据，也没有发送任何玩家日志。**

## 复现

在仓库根目录、安装 Godot 与 Python 3 的 Linux 环境执行：

```sh
python tools/benchmarks/run_endless_replay.py --output /tmp/endless-replay-v5.json
```

可用 `--godot /path/to/godot` 指定程序。运行会创建并清理自己的临时 HOME；输出结果只有显式给出 `--output` 才保存。不读玩家存档，不触网，不改生产配置。脚本固定直接加载 `endless_world_v5.gd`，不会随默认 v6 或未来规则悄悄变化。逐场景最多等待 180 秒。

原始测量数组：[`endless-replay-v5.json`](endless-replay-v5.json)。JSON 包含 5 次重放、5 次解析、内存采样与末尾非法动作拒绝数据。

## 方法与边界

- 3 种**人工合成的合法旅程** × 1,000 / 10,000 动作，固定种子 42。不是玩家行为采样，也不声称这些分布代表平均用户。
- `corridor`：领取起始物品后在两格安全区域反复行走，表示廉价动作基线；不能拿它单独估算完整游戏。
- `primary` / `alternate`：通过真实 BFS 导航、领取成长、使用补给、经过主/支路线敌人并换层。生成阶段不改 HP/金币或注入状态；最后一个动作为 `retire`，总动作数精确一致。
- 每个场景独立 Godot 进程，先生成日志并完成一次预热。计时仅包围 `W.from_data(decoded)`，不含进程启动、夹具生成、JSON 解析及结果断言。JSON 解析另测。
- 每次重放后检查规范存档、`summary()` 与地图变化 `deltas` 完全一致。另验证附加 `score` 字段被拒绝，退役后追加动作被拒绝。
- 时间是 `Time.get_ticks_usec()` 得出的**本机墙钟耗时，不是 CPU 时间**。五次样本只列中位数/最大值，不伪称可靠 p95/p99。
- `live_replay_alloc_delta_bytes` 是重放后尚存结果对象带来的 Godot 静态分配增量，不是临时分配峰值。Godot static peak 是整个进程累计峰值，包含引擎/夹具。
- Python 每 5 ms 读取 Linux `/proc/<pid>/status` 的 VmHWM；采样可能漏掉退出前最后峰值。RSS 包含引擎、夹具、断言副本及分配器，不可当成每条请求内存成本。

## 实测结果

| 场景 | 动作 | 最深层 / 击杀 | JSON 字节 | 重放中位数 ms | 重放最大 ms | 结果存活内存增量约 KiB | 进程采样 RSS 峰值 MiB |
|---|---:|---:|---:|---:|---:|---:|---:|
| 安全走廊 | 1,000 | 1 / 0 | 4,065 | 6.496 | 6.963 | 38.5 | 68.5 |
| 安全走廊 | 10,000 | 1 / 0 | 40,065 | 50.135 | 52.575 | 298.0 | 68.7 |
| 主路线 | 1,000 | 37 / 37 | 4,353 | 118.953 | 126.128 | 63.8 | 68.5 |
| 主路线 | 10,000 | 371 / 370 | 43,025 | 1,376.914 | 1,393.604 | 556.9 | 68.7 |
| 支路线 | 1,000 | 40 / 80 | 4,377 | 150.307 | 162.546 | 67.1 | 68.4 |
| 支路线 | 10,000 | 400 / 800 | 43,257 | 1,463.292 | 1,567.585 | 589.0 | 68.7 |

JSON 解析约 0.08–1.18 ms；这组样本主要成本在规则重放，而不是解析。相同动作数换层/战斗比原地行走昂贵得多。

退役后追加一个非法动作，10k 主路线仍花约 **1,415 ms** 才拒绝，支路线约 **1,582 ms**。因此“非法提交最后会被拒绝”不等于低成本：必须在完整验算前限流、验票和限制日志大小，不能让任意匿名请求无限触发重放。

这些数字不能外推 100k 动作性能、并发、跨版本复杂奇遇或真实网络延迟；它们也不是严格最坏情况。10k 路线仍有可接受本地运行耗时，不意味着免费边缘 CPU 预算够用。

## 对全球榜架构的实际含义

1. **不能把 Godot 基准当 Worker 基准。** Worker 不是可以直接启动该 Linux Godot 可执行文件的普通主机。当前 GDScript 核心依赖 Godot 运行时、Variant/Dictionary/Vector2i、脚本继承与地图生成；现有文件不能作为 JavaScript Worker 原样部署。嵌入运行时或改用其他执行服务是另一项工程，本次没有实现或验证。
2. Cloudflare 官方免费预算为每次 10 ms CPU，而本次测的是 Linux 墙钟；不作直接换算。结果足以否定“日志很小所以验算肯定便宜”的假设，**不足以证明移植后的 JS/WASM 一定超时或一定免费可行**。Supabase 2 秒 CPU 也不能用本机 1.46 秒墙钟推断安全裕量。
3. 语言移植成本主要是保证完全一致，不是把评分公式翻译几行：种子 RNG、整型范围、生成器布局、战斗舍入、跨楼层变化、货物/奇遇/训练状态、确认动作规范及版本继承都要逐状态对齐。不能漏掉合法性验证只算最终得分。
4. 当前应先维持本机榜。下一步可为单个冻结竞赛规则版本准备少量黄金轨迹，选取代表性核心函数做离线 JS/WASM 试验，与 GDScript 每步结果比对；在没有一致性证据前，不开放正式成绩提交。
5. 若要避免全面移植，可评估支持真实 Godot headless 的隔离验证工作进程，但会新增服务器/容器、队列、并发、资源限制及常驻费用，不自动认定比 Worker 便宜。本次没有选择、购买或安装该服务。
6. 大日志若分段，应接续服务器已验算的检查点，不能信任客户端 HP/金币。次数与段大小要根据真实边缘测试确定；不能因为拆分就宣称防作弊完成。
