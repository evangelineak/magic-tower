## 空间：两种真正不同的选择

`tools/audit_endless_v16_bridge_space.gd` 使用独立 BFS，而非把生产 validate 当 oracle。64 seeds × 层 [1,2,3,4,17,50,100,1000000] 共 512 生成样本，其中 47 个桥楼层分别测试 closed/short/loot 三种状态，共 141 分支地图、2,487 检查通过。

空间夹具明确设置分支派生状态，用于验证地图，不冒称这些状态都由真实钥匙获得；合法获取另见下节。

- 所有状态禁止零战入口到出口。
- closed/loot 的主路一守卫、支路两守卫各自双向通行、每位指定守卫不可绕过。
- short **按设计允许绕过 (8,8)**，但原怪仍在；只打开 (7,8) 桥进入隔离 (7,9)，第二怪 (8,9) 必经。不会错误沿用“支路两个怪永远不可绕”断言。
- 宝岛只在 loot 可达，额外 c(6,4) 是到 B(6,3) 的真割点；closed/short 宝岛不可达。这里是明确封闭的待选择内容，不是要由 v15 孤岛修复器擅自打通的装饰孤岛。
- 只有所选桥格变成 `.`，另一臂始终阻挡。
- 原 D 仍真正切断有价值奖励，V 仍挡 T，即使其他守卫/门全开也无侧路；楼梯及下一层实际落点同坐标。

原始：`endless-v16-bridge-space.json`。仅这些种子/深度抽样，不是全种子空间证明。

## 真实行为与原生文件：311 检查通过

`tools/audit_endless_v16_bridge_actions.gd` 在实际首层桥 seed 1 分别执行两条合法历史，没有给玩家注入钥匙、位置或金币：

1. 真实取训练/补给，避开钥匙先到绞盘验证无钥匙拒绝；远处确认请求也拒绝且不改事件。
2. 真实拾取 k，回绞盘；未确认请求只给确认，生命/钥匙/日志不动。
3. 确认后只扣一钥匙，记录对应选择；重复或另一选择均不可改选、不可再扣。
4. 合法分叉测试陈旧确认：提出桥确认后，真实把钥匙花在原 D 门，再回绞盘确认，拒绝免费开桥；该历史也可完整重放。
5. 直接走到未选桥前尝试进入，拒步且不写日志。
6. short 实走时禁止经过主怪和第一支怪，仍可到第二支怪并战斗；第一支怪还活着。
7. loot 真实打额外守卫、进 B，恰获 1 护符+1 凿甲钉，金币不变；重走空箱格不复制奖励。
8. 两分支都真实上二层再通过配对楼梯返回一层，选择不重置。clone 不共享可变 bridges 字典。
9. 两阶段历史逐个真实动作写入临时 native 文件，再从新 Store 对象读回，选择/钥匙一致；伪造额外 `bridges` 字段、追加非法二次选择事件均拒绝，原文件字节不变。

最终合法样例：short 38 个事件，HP 142/钥匙 0；loot 48 个事件，HP 120/钥匙 0。短样例说明选择确实改变行动与战斗，不是 50/100 层平衡结论。

**库存边界另行标记为受控夹具：** 3 个 clone 分别设为 9/0、0/9、9/9，道具任一满时整箱拒绝，不移动、不部分领取、不消箱；8/8 可完整收至 9/9。没有宣称这四个库存状态是通过合法赚钱/购买攒出来的。另一个受控 clone 清空可达敌、保留已锁宝岛守卫，验证站入口且有100金币仍不能因不可达守卫被收铭文费用；也不声称该清层状态是合法实走历史。它们计入 311 项中，原始字段也明确标记。原始：`endless-v16-bridge-actions.json`。
