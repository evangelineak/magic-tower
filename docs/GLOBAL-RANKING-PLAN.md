# 全球排行榜实施建议（尚未实施）

核实日期：2026-11-09。价格均为美元，来自下列官方页面；启用服务前须再次核对结账页、税费和账号现有用量。本次只读研究，没有创建账号、部署后端或上传玩家数据。

## 当前边界与推荐

当前游戏只有**本设备历史榜**：原生独立文件、Web localStorage，记录带规则版本。客户端重放能发现损坏和非法事件，但玩家控制客户端与存储，不能把这些记录直接认证成全球成绩。GitHub Pages 是静态托管，不能独立承担共享成绩数据库与可信验算 [1]。

推荐：保留现有 GitHub Pages 游戏入口，另用 **Cloudflare Worker + D1** 提供小型排名 API。先做离线规则验算和性能基准，再选择免费试运行或付费。`workers.dev` 可提供 API 地址，不需要先买域名 [2]。第一版定位为“服务器验算的休闲挑战榜”，不是保证真人、公平竞技或奖金比赛。

Supabase 是备选：若近期确实要账号恢复、跨设备身份、完整用户系统，其托管 Auth/Postgres 更合适；仅为一张榜引入它，最低付费成本与运维面更大。两者都不能代替游戏规则的服务器验算。

## 官方额度与付费触发

| 方案 | 免费关键限制 | 付费及超额 |
|---|---|---|
| Workers [3] | 10 万请求/日；每次 CPU 10 ms | Standard 基础 $5/月，含 1000 万请求与 3000 万 CPU-ms/月；超额分别 $0.30/百万请求、$0.02/百万 CPU-ms。默认每次 CPU 30 秒，可配置至 5 分钟。 |
| D1 [4][5] | 500 万行读取/日，10 万行写入/日；账号总 5 GB，但**单库仅 500 MB** | Paid 含每月 250 亿读、5000 万写及 5 GB；超额 $0.001/百万读、$1/百万写、$0.75/GB月。D1 无出站流量费。 |
| Supabase [6][7] | 500 MB 数据库，5 GB 普通出站流量，50,000 MAU；50 万函数调用/月；闲置一周可能暂停项目 | Pro 从 $25/月起，含首个项目额度；函数含 200 万次/月，超额按每百万 $2 整包进位；其他项目和资源可能另计。 |

关键区别：

- D1 免费读写耗尽会拒绝查询，存储满会阻止新增，并非悄悄自动升级。Paid 超额按量计费 [4]。
- Worker 单次 CPU 上限有助防止费用攻击，但不是整月总账单硬上限；缓存能降低重复验算/数据库负担，不能假设经过 Worker 的缓存命中完全免请求费 [3]。
- Supabase 免费套餐不计费；Pro Spend Cap 只覆盖部分项目，**不覆盖 compute 等所有费用**，也不是任意金额的统一预算封顶 [8]。
- Supabase Edge Function 每次 CPU 仅 2 秒、内存 256 MB；150/400 秒是墙钟时长，不是可用 CPU 时间 [9]。
- D1 单行/string/BLOB 上限 2,000,000 字节 [5]。不要误把本地 2 MiB 存档阈值视为可直接写入 D1 的安全大小。

**预算建议**：先保持免费、超过资源阈值时暂停排行榜提交，游戏离线功能不受影响。不自动升级；如验算确需付费，另请用户批准 $5/月基础订阅及明确超额政策。不能承诺“永远免费”。

## 可信提交协议（建议，未实现）

1. 玩家主动进入“在线挑战”，服务端发放 `run_id`、规则版本/规则摘要、挑战种子、赛季、身份绑定、有效期与不可伪造票据。普通离线旧档不能补造开局票据成为正式挑战成绩。
2. 客户端只交票据与有序动作，不交可信 HP、金币或楼层。服务器从确定的初始状态完整重放，再自行计算成绩。排行榜写权限只给后端；公开客户端密钥、CORS、混淆和本地校验都不是防作弊边界。
3. 同一 `run_id` 只能结算一次；数据库唯一约束、事务/CAS、日志摘要处理重复请求与并发。相同提交重试返回原结果，改过的重复提交拒绝。不能以客户端 run_id 或昵称作为身份认证。
4. 大日志分段时，只允许接续**服务器已验算的检查点**，绑定动作序号、规则和前序摘要；不接受客户端上传的中途数值。每段幂等，结算不能跳段；设计中途失败恢复与过期清理。
5. 限请求体、解压后大小、动作数、执行 CPU、单身份/短时网络来源请求率、并发和每天开局数；未知版本/动作立即拒绝。异常不能导致自动付费扩容。
6. 榜单只查索引后的 Top N、分页及缓存；公开读取不返回日志、票据或私密身份信息。服务故障时明确“待提交/未入榜”，不能显示成功后丢成绩。

## 验算成本与本地先行验证

当前 DTO 为 `version/mode/seed/actions` 四字段，最多 100,000 个动作。紧凑 JSON 的粗略量级：10 万个单字方向约 0.40 MB，带确认的方向约 0.50 MB，10 万个长度 16 的指令约 1.90 MB（只是结构上界，重复指令不一定是合法旅程）。额外元数据、Unicode 与传输编码还会改变大小。不要长期保存所有长日志在单个免费小库里。

现有 Godot/GDScript 核心不能假装已经能在 Worker/Edge Function 执行。需提取纯规则为 JS/WASM 或另选支持现有运行时的验证服务，且保留各规则版本。移植必须核对 RNG、整数边界、生成器、战斗舍入、动作合法性和结束条件；仅两端都得出一个“看起来合理的分数”不够。

先用合成且合法的 1千/1万/10万动作旅程测 p50/p95/最大 CPU、峰值内存、报文大小；加最坏换层、回访、战斗、奇遇、非法末尾和截断日志。并逐动作比较原生与验算器状态摘要。**尚无生产边缘运行时 CPU 测量，不能断言免费 10 ms 或 Supabase 2 秒够用。**

示例仅演算：假设每月 1 万次验算、每次 100 ms，则需 100 万 CPU-ms；它在付费 CPU 包含量内，但每次都超过免费 10 ms，不能因此宣称免费可跑。真实费用还取决于开局、分段、读榜、失败/攻击请求和存储。

## 公平性、身份与不可消除的作弊

- 以 `(规则版本/摘要, 赛季, 挑战种子, 模式)` 分榜。v1 与 v4 即使同层数也不是同难度，不能只加小字却仍称统一公平榜。正式榜仅开放已部署验证器的明确版本；旧版保留历史榜，未知新版拒绝。
- 推荐每日/每周固定种子的挑战榜；自由种子另作探索纪录，避免反复挑最简单种子。公布排序公式、并列规则、重试次数和截止时间；耗时若无法可信测量，不作为主要指标。
- 同种子仍可先离线练习、分享路线或跑求解器；服务器重放证明“规则上可达”，**不证明真人游玩、无辅助或亲自探索**。一人多匿名账号也不能靠重放解决。
- 匿名方案使用服务器分配的随机公开 ID 与不同的私密会话凭据。昵称是展示文字，附 ID 后缀，不宣称实名认证；默认生成昵称可降低冒名与内容审核风险。凭据不放 URL、公开仓库或日志。
- 无登录不能可靠恢复清空缓存后的身份，也不能证明唯一自然人。删除本地数据后重新开号、借用身份与脚本批量注册仍有风险；不能承诺“一人一次”。网络限流会误伤共享网络，也无法阻止分布式刷榜。
- Supabase 匿名登录本身仍创建数据库用户；官方提醒有滥用风险，默认按 IP 限 30 次/小时，建议验证码，且没有自动匿名用户清理 [10]。接入验证码/额外服务需单独考虑隐私与玩家体验。

## 隐私最小化（待用户批准）

建议玩家首次提交前明确告知：接收方 Cloudflare、用途为成绩验算/排名、公开字段、保留时间和删除方式。拒绝不影响本地游戏；不自动上传已有存档。

- **公开**：随机公开 ID/可选昵称、服务端算出的成绩、规则版本、挑战/赛季、粗粒度提交日期。金币/击杀仅在明确的成绩公式需要时展示。
- **私有最小集**：运行票据与状态、日志摘要、验算日志、受保护会话标识、提交时间。日志建议保留 7 天用于重验，公开成绩保留当季及约定历史期；这些是产品建议，不是已启用策略。
- 不收姓名、邮箱、设备指纹、通讯录或地理位置；应用日志不记录请求正文/凭据，尽量不持久保存原始 IP。若反滥用需短期网络标识，另明确用途、期限与删除机制。
- “不主动收集”不等于服务商不处理网络元数据。GitHub 已说明 Pages 访问会记录 IP 用于安全 [1]；新增后端也会接收连接元数据，须核对服务商隐私政策、日志设置与数据区域。
- 提供凭据持有者删除/隐藏自己的公开成绩入口；丢失凭据后的申诉流程不能仅凭同名昵称删除他人记录。

## 落地顺序与批准闸门

1. **现在可做的离线工作**：冻结竞赛规则，编写 DTO/协议与恶意提交测试、纯规则移植、跨语言黄金用例、合成日志性能基准。无需真实账号或玩家数据。
2. **选择服务前**：根据基准决定 Worker 免费是否可行；不满足则比较 $5 付费与不同运行时，不为迁就费用降低验算。
3. **需用户明确批准**：使用谁的 Cloudflare 账号创建 Worker 与 D1；先只免费还是接受周期订阅及多少超额；部署目标/公开 API；匿名还是可恢复登录；公开字段、玩家告知与保留/删除政策。平台要求的登录/授权/凭据及计费确认仍照做。
4. **批准后隔离试点**：只用假身份/合成日志，验证限流、未知规则、重复并发提交、费用熔断、数据删除、服务故障降级与浏览器跨域。只允许游戏来源的 CORS，但不把它当认证。
5. **再开放自愿提交**：先无奖金休闲挑战榜。上线后观察真实 CPU/读写、错误率及滥用，再决定是否加登录；全球榜掉线不能破坏本机档。

验收底线：未部署可信验算、未实际跨设备读到同一榜之前，UI 和文档不得把本机榜标成“全球排行榜”。本计划本身不构成服务已创建或已获得费用授权。
