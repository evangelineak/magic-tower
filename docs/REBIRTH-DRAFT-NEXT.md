# 轮回策略抽选：开发实现与验收边界

真实死亡及唯一终局收据已验证。本批实现以下规则，整体验收记录见 VERIFICATION.md，公开网页未同步。没有真钱抽取，不把尚未选用的解锁标识误称已经生效的天赋。

- 成功结算的首次3/5/8层记录只扩展横向策略池，不反复自杀刷永久攻防。
- 每个新局按塔种子、规则版本和当前解锁池生成最多三个明确候选，并始终允许原装。创建旅程时原子保存实际候选，读取、撤销、重试不重抽。
- N换种子可换塔和候选，允许玩家找喜欢的构筑。不为防止无付费、无稀有度的开局选择而设计复杂反刷；同一seed/池/版本应可复现。
- 每局最多启用一个策略，第一次实际行动前明确锁定，之后不靠Undo更换。选择应有看得见的代价，原装仍是可通关基线。
- 优先少量可被战斗预览完全解释的构筑：攻防取舍、技能等级与基础战力取舍。数值通过真实敌人组合及路线测试决定，不直接堆无限百分比。若实现额外技能等级，必须显示真实来源、上限和效果，只有实际可达20才宣传20级。
- 模式（safe/risk）、跨局策略、局内装备词条和普通击杀天赋分栏，避免将四种不同概念混作抽卡。
- 使用既有profile唯一收据作为解锁来源。旧schema活动局不补抽、不改变地图或属性；下一明确新局才使用新解锁池。

已覆盖的验收：候选持久化/同请求去重/跨窗口、原装基线、每个策略至少一种更合适与一种更差对局、正常行动后不能换策略、存档升级不凭空领奖、死亡/退役/胜利后新局保留档案。完整范围与平台限制见VERIFICATION最新记录。

## 当前实施决策

schema15保存nested `draft={version,pool,offers,choice}`，空choice表示待选，不另存冗余locked。出生池由当前profile在create事务派生，不信任UI传来的解锁；无池自动原装，有池必须明确选候选或原装。旧<=14为rev0空池原装，不补抽。choose单次CAS保存、profile不变、move不增加，成功后清Undo；普通save/Undo不能切换已锁选择或出生池。

首达3层池含study/forager/channel/reserve，5层加ambush_hunter，8层加last_gambit，最终6取最多3，所以候选会真正变化而不是仅换顺序。下列数值已通过敌人矩阵验证，实玩与整体验收单列记录：
- study：技能等级+4，有效攻击-4/防御-2；训练与装备凑齐才真实到20。
- forager：存活击杀后回血12，杀怪金币扣ceil(25%)；其他收入不扣，死亡不回血。
- channel：击杀原始HP>=180强敌后恢复1专注（受上限），有效防御-3；先扣本战使用专注再领奖。
- reserve：有效攻击-3，未armed战斗有效防御+4，armed不加防。
- ambush_hunter：敌有真实未被誓约/侧袭抑制的先制时有效攻击+6，否则-2；防御始终-2。
- last_gambit：开战HP<200时有效攻击+6；防御始终-2，条件按开战HP固定。

这些是本局策略，不把基础攻防写成永久增长。预览、技能说明、时间线和死亡重放必须使用同一策略上下文。普通none仍保持原战斗结果，保留原装选择与安全默认。
